# Build——按风险实施

把已确认方案变成全绿 tasks。快速模式不进入 Build。

## 前置与分支落点

- 读取 proposal、tasks、相关 `.ai/memory` 和实现计划（仅严格），从第一个未勾任务恢复。
- 发现范围冲突、必要依赖缺失或风险升级，停止并更新事实源，请求重新确认。

### 标准模式

`模式: 标准`、`状态: 待确认计划`且唯一实施确认已获得后，实施前必须完成：

1. 记录当前基线分支并检查状态；区分本变更四件套与用户/其他变更。
2. 若尚无 feature，创建并切到 `feature/<变更名>`；只暂存本变更四件套，把状态置为`构建中`并提交。不得在 main/master 写实现。
3. 仅本变更产物导致工作区非空不算“用户脏工作区”。若存在用户修改、并行实现、高冲突或用户要求隔离：提交明确文件后先切回基线，再用 git-worktrees 挂载当前未检出的 feature 分支；不要对已检出的分支执行 `worktree add`。
4. 无隔离条件时留在 feature 分支就地实现。恢复已有 feature/worktree 时只核对，不重复创建。

无法把本变更文件与用户修改安全分离时停止请求决定。

### 严格模式

proposal 必须已是`模式: 严格`、`状态: 构建中`，并位于 Design 准备好的 feature worktree。若仍在 main/master 或 feature 分支同时被其他工作区检出，停止修正落点后再实现。

## 执行路径

| 情形 | 执行方式 | 审查 |
|---|---|---|
| 标准小型、边界清晰任务 | 主会话直接逐职责单元执行 | Build 内自查；完成后交 Verify 一次综合审查 |
| 标准任务可独立并行、规模较大或需隔离判断 | 按需使用 subagent-driven/parallel-agents | 不默认每任务双审；完成后仍只做一次综合终审 |
| 严格 | 使用 subagent-driven；不能安全派发时主会话按同等纪律直执 | 每任务规格与质量审查，之后交 Verify 双阶段审查 |

## 每个职责单元

1. 为运行时行为或缺陷修复使用 tdd：先写并运行失败测试，再写最小实现、跑绿并重构。
2. 纯文档、注释、知识库或流程文本不用形式化红—绿，改用内容契约、结构、示例、格式和 diff 校验。
3. 运行任务指定验证，读取退出码和完整相关输出。
4. 按所选模式完成自查或任务级审查；严格任务级审查先由主会话 freeze 精确范围，reviewer 按 `.ai/rules/review.md` 在读取前和结论前 verify，同一 manifest 任一 `STALE` 都立即停止；标准模式的唯一完整综合审查留给 Verify；通过后勾选对应 tasks。
5. 按可独立回滚的职责单元提交。一个提交可覆盖多个机械 checklist，一个职责单元不得无故拆成提交噪音。

测试失败或出现意外行为时，必须先用 systematic-debugging 定位根因；解决新坑立即写 `.ai/memory/<模块>.md`。审查意见先验证，有理再改，无理用证据说明。

## 子代理契约

只有执行路径命中时才加载 subagent-driven。派发内容包括边界明确的任务简报、前序接口、相关 memory 摘要、适用的测试纪律、验收命令与报告路径；审查者使用独立上下文、有效 manifest 和精确 diff，不继承实现者判断。有限角色契约见 `.ai/prompts/agents/`；快速模式与边界集中的标准小任务不因角色存在而机械委派。

标准小任务不得仅为形式创建 SDD 台账、实现代理、任务审查代理和全分支终审组合。

## 出口

以下全部满足才把状态置为`待验证`：

- tasks 全勾；
- 目标与相关回归测试全绿；
- 命令输出证据和 diff 已亲自核对；
- 严格模式任务级审查无未决 Critical/Important。

finding、差异复审、未验证范围和残余风险统一执行 `.ai/rules/review.md`。已确认范围内最小修复沿用现有授权；只有新增未确认行为、依赖、迁移或外部副作用才暂停并重新确认。

没有新鲜证据不得声称构建完成。交 Verify，不在 Build 重复全分支终审。

## 常见错误

| 错误 | 正确处理 |
|---|---|
| 标准确认后仍在 main 直接实现 | 先创建/切到 feature 并提交明确四件套 |
| 标准单文件任务默认派四类代理 | 主会话直执，留一次综合终审 |
| 文档任务制造形式化 TDD | 使用内容与结构验证 |
| 每个勾选项机械提交 | 按可回滚职责组织提交 |
| 测试红时试探性修复 | systematic-debugging 先找根因 |
