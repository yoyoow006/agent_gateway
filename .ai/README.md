# 共享 AI 知识层

`.ai/` 是 Claude、Codex 等助手共享知识的唯一正文来源；助手私有目录只保存工具适配和技能。OpenSpec 仍是标准/严格变更状态与进度的唯一真源。

## 目录归属

| 路径 | 内容 | 写入时机 |
|---|---|---|
| `kb/` | 稳定架构、项目卡、公开契约和验证证据 | 权威事实变化并经核对后 |
| `rules/` | 硬约束与按需读取路由 | 路由或治理规则变化时 |
| `memory/` | 跨会话踩坑与可复用解法 | 坑定位并解决后立即追加 |
| `prompts/` | 共享轻量角色契约 | 角色职责确认后 |
| `tools/` | 确定性、只读、有界的事实工具 | 通过对应测试后 |

## 读取与写入

- 先读 `rules/index.md`，只加载命中任务的项目卡、契约和 memory。
- 项目是否已检出由工具运行时观察；不得把观察结果写回项目卡或 registry。
- 不在 `.codex/ai-kb` 或 `.claude/ai-kb` 新增正文，也不把 prompts、manifest 当作任务状态。
- 新坑使用 `memory/README.md` 的格式；稳定事实与经验分开保存。

共享层不自动联网、clone、修改业务仓或输出配置值和敏感正文。

## 安装到其他项目

本仓库的 `scripts/install-ai-workflow.sh` 可将通用共享层和 Codex 或 Claude 单侧适配安装到已存在的项目目录。安装命令、冲突策略、退出码和 OpenSpec CLI 边界见 [tools/README.md](tools/README.md)。

安装包只包含空白通用骨架，不携带源项目的业务知识、活跃变更、归档、本地状态或 memory 正文。安装器不覆盖差异内容；目标已有助手入口时，必须由目标维护者审查并人工整合。
