# 子代理驱动开发

子代理用于隔离真正独立的工作，不是所有任务的默认仪式。

## 触发边界

| 情形 | 决策 |
|---|---|
| 快速模式 | 不使用子代理 |
| 标准小任务、单文件或单一职责 | 主会话直执，不创建 SDD 简报/报告/多层审查组合 |
| 标准模式有多个独立任务、规模较大或需要隔离判断 | 可按需派实现者；最终仍至多一次综合审查 |
| 严格模式 | 默认逐职责单元派全新实现者，并执行任务级规格与质量审查 |
| 任务共享状态、修改同一核心文件或有顺序依赖 | 串行，不并行派发 |

## 工作区

只有命中触发条件才创建 `.codex/sdd/<变更名>/`：

- `progress.md`：计划路径、BASE、任务状态和修复轮；
- `task-N-brief.md`：单任务完整契约；
- `task-N-report.md`：提交、测试、疑虑；
- `review-<base>..<head>.diff`：精确审查包。

SDD 是 Git 忽略的本地恢复资料。开始前用 `git check-ignore` 验证；不得读取其他变更的 SDD 目录。

## 派发契约

每个实现者获得：

1. 单一职责、精确文件范围和不可修改项；
2. 前序接口及相关 ai-kb memory 摘要；
3. 适用的 TDD 或非运行时内容验证规则；
4. 验收命令、预期结果和报告路径。

有限角色只使用 `.ai/prompts/agents/` 的共享契约：explorer 只读，reviewer 独立只读，test worker 只在明确测试范围写测试或运行验证；助手 adapter 不扩展共享算法。

使用全新上下文，不粘贴主会话推理。实现者只回状态、提交哈希、测试摘要和疑虑，完整证据落报告。

## 执行循环

### 标准模式按需派发

实现者完成后，主会话核对 diff、测试和范围，勾选 tasks 并按可回滚职责提交。Build 不再追加每任务双审或全分支终审；Verify 负责唯一综合审查。

### 严格模式

每个职责单元固定循环：

1. 记录 BASE，派全新实现者；
2. 核对报告、提交与测试证据；
3. 主会话先 freeze 任务精确范围；独立 reviewer 按 `.ai/rules/review.md` 在读取前和结论前 verify，同一 manifest 任一 `STALE` 都停止，再检查规格符合性和代码质量；
4. 有 Critical/Important 时先核实，把精确问题退回同一实现者；已确认范围内最小修复沿用授权，主会话重冻后只复审 delta、直接消费者和继承 finding；新增未确认行为、依赖、迁移或外部副作用时停止并重新确认；
5. 通过后勾选 tasks、提交或确认提交存在，再进入下一项。

最多五轮仍不能收敛，或实现者报告缺上下文/计划错误时，停止并升级给用户；不得无变化地强令重试。

## 并行与恢复

- 只有文件、状态和顺序都独立的任务才能使用 parallel-agents；同批修改同一文件就不独立。
- 上下文压缩后以 tasks、`progress.md` 和 Git 历史恢复；提交与台账不一致时先核实，不重复派已完成任务。
- 全部实现完成后回 Build 出口；严格模式的任务审查不能替代 Verify 双阶段审查。finding 状态、未验证范围、残余风险和 `accepted-risk` 用户决定统一记录于共享审查台账。

## 常见错误

| 错误 | 正确处理 |
|---|---|
| 标准小任务默认建一套 SDD 和四类代理 | 主会话直执 |
| 实现者与审查者共享结论 | 用精确文件材料和独立上下文 |
| 并行修改共享文件 | 串行或重新切分边界 |
| 控制者悄悄修代理问题 | 严格模式退回实现者并复审 |
