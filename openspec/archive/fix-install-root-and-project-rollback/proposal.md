# 修复安装示例与根目录/项目创建边界

## Why

代码审查发现三个会直接破坏安装和使用体验的问题：

1. README 与使用指南的供应商 `base_url` 示例带 `/v1`，而网关会自动拼接协议路径，实际请求变成 `/v1/v1/...`，按示例配置会全链 404。
2. 显式 `--root` / `AGW_ROOT` 未按文档校验 `config/` 存在，错误根目录会被静默接受，甚至自动生成 `config/local.toml`。
3. `agw project new` 先创建项目、写模板、git init，之后才读取配置；配置无效时命令失败但留下半成品项目目录，重试报“项目已存在”。

## What Changes

- 修正文档中的 OpenAI/中转站 `base_url` 示例，统一使用域名根，明确不要携带 `/v1`。
- 让 `resolveRoot()` 对显式 `--root` / `AGW_ROOT` 执行与文档一致的网关根校验：目标必须存在 `config/` 子目录；无效时失败退出，不加载、不写盘。
- 调整 `workspace.New()` 顺序：先加载并校验现有配置，再创建项目目录与写入 token；配置加载失败时不得产生项目副作用。
- 补充配置/CLI/工作区回归测试与安装说明示例校验，锁定上述行为。

## Impact

- 用户可避免按快速开始配置后请求 `/v1/v1/*` 导致不可用。
- 拼错 `--root` / `AGW_ROOT` 时会立即得到明确错误，且不会在错误目录生成密钥配置。
- 无效配置下 `agw project new` 不再留下半成品目录；项目已存在仍保持原有错误。
- 不改变协议转发语义、供应商排序、热重载协议或其他 F-003~F-012 范围。
