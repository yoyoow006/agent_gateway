# design

## 决策

1. **字段放在供应商级而不是全局级。** 同一客户端模型在不同供应商上的可用目标模型不同；供应商级 `default_model` 与现有 `model_map` 生命周期一致，并可直接随 `agw provider add` 管理。
2. **引入统一模型解析函数。** 新增 `resolveModel(model, profileMap, provider)` 返回目标模型：先合并档案级与供应商级映射（供应商级优先），精确命中返回映射值；未命中且 `provider.DefaultModel != ""` 返回兜底值；否则返回原模型。同协议与跨协议路径都调用该函数，避免两个路径规则漂移。
3. **同协议仍保持最小改写。** 配置了 `default_model` 后不能放弃透传快路径，继续复用 `applyModelMap` 的顶层 `model` 精确定位替换，除该字段外不重排 JSON 字节。
4. **三层合并采用非空覆盖。** 与其他供应商标量字段一致：local/project 中出现非空 `default_model` 即覆盖；无法用空字符串表达“清除”。需要清除时删除该键或整条更新供应商，这是现有配置模型的既有边界。
5. **CLI 只做字段管理。** `agw provider add --default-model` 新增/更新供应商时写入；不带该 flag 且更新既有条目时按现有 `provider add` 的替换语义清空，避免隐藏旧值导致配置与命令意图不一致。

## 替代方案

- **按协议维护全局默认模型表：** 无法表达同名请求模型在不同中转上的不同安全回退目标，且与项目档案映射叠加会产生更多隐式规则。
- **在解析配置时把 `default_model` 展开成特殊映射键：** 无法可靠枚举未知客户端模型，也不适合实现“所有未命中模型”的语义。
- **未知模型直接返回 400：** 能快速暴露配置落后，但违背本变更目标中的自动可服务性。

## 风险与边界

- 兜底模型可能不支持原请求能力（上下文长度、工具、reasoning 等），上游仍可能返回业务错误；该错误按现有 failover/错误透传机制处理。
- `default_model` 空字符串不作为清除语义；清除由删除配置键或整条更新供应商实现。
- 同协议透传只有成功解析出顶层非空 `model` 才可能改写；无 `model` 的 GET 保持原样。
- `/v1/models` 不额外把 `default_model` 发布为模型 ID，避免客户端把兜底目标当作可请求名；已有精确映射仍照常发布。
